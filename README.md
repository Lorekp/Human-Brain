# Human Brain

Human Brain is a cell-only autoregressive language and program-learning
research system. Its learned state and inference are implemented with simulated
human cortical cells: dendritic branches, Allen human-data-fitted GLIF cells,
sparse recurrent synapses, spike eligibility, and output-cell races.

It is not a transformer, a dense artificial neural network, a pretrained
embedding model, or a claim to simulate an entire biological brain.

## Repository family

This is an independent sibling of two other simulation projects:

- [DeepSim](https://github.com/Lorekp/DeepSim) — robot simulation,
  qualification evidence, and policy delivery;
- [Fly Brain](https://github.com/Lorekp/Fly-Brain) — *Drosophila* connectome
  simulation and evaluation.

The repositories do not import or modify one another.

## Architecture

Two working sequence layers share the cell-only contract:

1. The dendritic GLIF3 layer grows sparse higher-order branches by replaying
   token sequences. Matching branches produce NMDA-like plateau drive, and a
   fast-spiking inhibitory race selects the next token.
2. The recurrent GLIF5 layer uses fitted voltage reset, after-spike currents,
   spike- and voltage-dependent threshold state, sparse recurrent dynamics,
   eligibility traces, and fitted output cells. This is the active scaling and
   free-running research path.

The recurrent token interval runs in native Rust; Python orchestrates
experiments and artifact handling. Large networks can use an NVRTC-compiled
CUDA backend. CPU and CUDA must match the deterministic state-transition oracle
before performance numbers are accepted.

For networks of at least 100,000 cells, the performance gate requires more
than 100 end-to-end tokens/s while retaining the frozen 0.05 ms integration
step, 5 ms token interval, sparse propagation, cell state, and output
computation. Dormant padding, fewer biological steps, and hidden non-cell
models do not count.

## Quick start

Python 3.11+, Rust/Cargo, and a C++ build environment are expected for a source
checkout. CUDA is optional.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[test]"
.\.venv\Scripts\python.exe -m pytest -q

$env:PYTHONPATH = "src"
.\.venv\Scripts\python.exe -m humanbrain.cli "Human cortical cells " --tokens 24
```

The GLIF5 path builds a content-addressed Rust kernel on first use and caches
the release DLL by source hash. Set `HUMANBRAIN_DEVICE` to `auto`, `cpu`, or
`cuda`, and use `HUMANBRAIN_NATIVE_CACHE` to choose an explicit native-cache
location.

### Native experiment visualizer

[Neural Observatory](docs/neural-observatory.md) is a GPU-rendered desktop
workbench for the canonical `experiments/<experiment>/<arm>.json` results. It
compares cohorts, shows uncertainty-aware outcome statistics, reports
neuroscience-relevant structural and representation diagnostics, queries exact
local topology from materialized or procedural networks, tails live activity,
and replays complete experiment traces from disk. Billion-neuron configurations
remain inspectable without creating one UI object per neuron, while long traces
remain seekable without retaining every decoded frame in memory.

```powershell
uv --cache-dir .uv-cache pip install --python .venv\Scripts\python.exe -e ".[visualizer]"
& ".venv\Scripts\python.exe" -m humanbrain.visualizer.cli experiments --experiment visualizer_demo
```

The frozen-protocol gates are re-frozen deliberately after source-changing
merges, never bypassed by weakening digest checks. The Gate-3 procedural
binding was regenerated against the post-merge sources (protocol pin
`21cf21af…`). The large-scale-capability protocol
(`benchmarks/large_scale_capability_protocol_v1.json`) still pins the
pre-campaign `cells.py` and related sources, so
`tests/test_large_scale_capability.py` reports freshness failures until that
preregistered protocol is reviewed and deliberately re-frozen. Separately,
the Simple-SWE freeze/reveal gates pin their sandbox to exactly
python-3.11 and fail by design on hosts whose interpreter is a different

### Procedural scale

One hundred billion cells is an addressable distributed-architecture target,
not a result. Future reports must distinguish addressable, materialized,
updated, and spiking cells. The first native counter64-v2 procedural slice has
bounded resident/event frontiers, deterministic event ordering, capacity
failure, uint64 identities, and fixed-work accounting across one million to
100 billion configured identities. It is correctness and resource-bound
evidence, not a speed or capability result.

See [the 100-billion-cell architecture](docs/research/100-billion-cell-architecture.md)
and [the Gate-3 procedural slice](docs/procedural-runtime-gate3-slice.md).

## Research directions

- [Biology-of-learning fusion survey](docs/research/a013-biology-learning-fusion.md)
  maps real plasticity mechanisms onto the implemented equations and finds the
  sparse three-factor rule already in the codebase (dormant during the sealed
  run). Ranked proposals: error-gated (RPE-style) three-factor plasticity,
  rest-phase replay consolidation, homeostatic margin normalization with
  critical-period scheduling — each with a decisive preregistrable experiment.
- Regioned architecture, representation choice, teaching-process matrix, and
  the cognitive-property roadmap are design inputs on master
  (`docs/research/a013-*.md`; catalogued in
  [the research index](docs/research/INDEX.md)). The first executed waves off
  this line are recorded honestly: U-STATE and APICAL-AND week-1 verdicts are
  negative with localization, and the T-ROUTE trained-mapping family is
  falsified in all three tested third-factor forms
  ([program conclusion](docs/research/t-route-program-conclusion.md)).
- Path 2 is the current mainline. Segment recognition and winner election now
  execute in native fitted-cell plateau/race dynamics, but C1 remains held.
  The source-bound calibration-v3 run terminated honestly at development
  R3-F0 with no selected arm; confirmation and held-out surfaces stayed closed.
  Failure localization now precedes any new repair, while the remaining
  controls, cap measurement, and CN-2 are still open
  ([verdict](docs/research/r3-calibration-v3-verdict.md),
  [readiness](experiments/r3_pilot/C1_READINESS.md)).
- [Indicator assessment instrument](docs/indicator-assessment/RUBRIC.md)
  tracks architectural similarity to consciousness-science indicator sets
  (RPT/GWT/HOT/AST/PP/AE families) across model versions using strictly
  categorical levels — ABSENT / PARTIAL / PRESENT / UNCERTAIN — as an
  early-warning review tool. It produces no numeric scores and makes no
  claims about subjective experience; indicator presence is evidence about
  architecture, not about consciousness.
