# Human Brain

An autoregressive language experiment whose learned state and inference are a
simulation of human cortical cells. It is a separate sibling project from
`../Fly Brain`; neither project imports or modifies the other.

There are now two working cell-only sequence layers. The dendritic layer is a
strong variable-order byte predictor. The recurrent layer uses Allen
human-data-fitted GLIF5 cells, sparse recurrent synapses, spike eligibility,
and output-cell races. It is the active scaling and free-running research path.

The current model grows dendritic branches by replaying token sequences. During
prediction, matching branches produce NMDA-like plateau drive in token cells
whose membrane, threshold, reset, and after-spike parameters are fitted to
Allen human layer-2 specimen `488392806`. The first cell to spike under
fast-spiking basket-cell inhibition emits the next token.

The current dendrites recursively discount sparse higher-order branches with
lower-order evidence. On the frozen code-language v3 test split, the cell race
predicted 3,889/4,500 bytes (86.42%) across three unseen files, versus 29.93%
for a train-only bigram and 86.40% for an evaluation-only same-order
Witten-Bell reference. The test split was opened once after validation choices
were frozen; there is no test-time growth.

A validation-only compiled membrane kernel preserves every prediction and spike
time while running the cell races at 5,358 byte tokens/s on the recorded gate.
The consumed v3 test split is locked and was not reused for this optimization.
A separate one-shot Python-standard-library cohort scored 37.97% across 7,500
predictions, versus 21.37% bigram and 37.85% matched Witten-Bell, showing the
domain-shift cost rather than tuning it away.

Free-running continuation is still weak: the current validation-only gate ties
an always-space unigram at 17.51% over 1,536 generated bytes. This failure is
recorded explicitly and is now the main capability target.

The recurrent scaling experiments identified and corrected a synchronized
reservoir failure. Under the calibrated sparse dynamics, increasing active
cells and training data together from 24/3,000 characters to 384/48,000 raises
median teacher-forced accuracy from 43.10% to 49.61%, free-running accuracy
from 6.25% to 12.76%, and effective state rank from 7.57 to 23.85. Dormant-cell
controls reproduce the compact circuit exactly, showing that useful active
dynamics rather than allocation alone cause the gain.

The recurrent token interval now runs in native Rust; Python only orchestrates
the experiment. The current ABI adds deterministic Rayon-parallel dense
execution and an algebraically exact quiescent-cell frontier. On the registered
natural sparse trajectory, 131,072 cells run at 754.17 tokens/s and 1,048,576
cells at 193.36 tokens/s. Those numbers are activity-dependent: the explicit
density stress at 131,072 cells records 176.15 tokens/s at 5% updated cells and
51.50 at 20%. Exact ridge consolidation still needs an `N x N` normal matrix
and an `O(N^3)` solve. The experimental native three-factor rule below removes
that hidden state and solve; its remaining limits are learning quality and the
physical `vocabulary x cells` readout.
For networks of at least 100,000 cells, a persistent-device CUDA backend
executes the full 100-step token interval in one cooperative launch. CUDA and
Rust match every mutable state array bit-for-bit; exact large-network
throughput is registered in `docs/simulation-speed.md`. On the
RTX 4070 SUPER, the isolated 200,000-cell run touched 1.2 million recurrent
edges per biological step at 144.03 end-to-end tokens/s, passing the strict
size/speed gate. The fixed-input run spiked sparsely, so this is a simulation
throughput result rather than evidence of useful large-network recruitment.

Simulation speed is a core capability requirement. The acceptance gate is
more than 100,000 **active** fitted human cells at more than 100 end-to-end
recurrent tokens/s on this workstation. A qualifying run must retain the frozen
0.05-ms integration step and 5-ms token interval, sparse recurrent propagation,
cell state, and output computation; dormant padding, fewer biological steps, or
a hidden non-cell model do not count. CPU and GPU backends must be checked
against the same deterministic state-transition oracle before their performance
numbers are accepted.

The stateful GLIF5 reservoir builds a content-addressed Rust kernel on first use
and caches the release DLL by source hash. The locked CPU crate uses Rayon for
deterministic cell chunks, so Rust/Cargo and the locked crates are runtime build
prerequisites for a source checkout; Python remains orchestration around the
native cell simulation. Large networks use an NVRTC-compiled CUDA kernel when
available. Set `HUMANBRAIN_DEVICE` to `auto`, `cpu`, or `cuda`, and set
`HUMANBRAIN_NATIVE_CACHE` to place compiled caches explicitly. See
`docs/simulation-speed.md` and `docs/native-scaling-v2.md` for the registered
CPU and GPU protocols and third-party license details.

An experimental native three-factor readout removes ridge's quadratic growth
state and cubic solve while leaving ridge as the default comparison. It reached
6,144 learning cells with 13.92 MiB traced peak memory, but did not match ridge
accuracy at small sizes and its free-running validation remains weak. See
`docs/local-readout-learning.md` and the frozen
`artifacts/local_learning_scaling_v1.json` report.

An explicitly non-capability smoke also exercised online updates at 98,304
cells with 211.70 MiB peak memory and no quadratic ridge state.

Direct `O(cells * fanout)` builders now construct one-million-cell grouped,
mixed-membership, 1D, 2D, layered, and 3D circuits with six million edges in
15.74-48.43 seconds and 22.89 MiB of target arrays. This removes the old
population-sized candidate-row bottleneck; it does not establish that any
topology improves prediction.

One hundred billion cells is tracked as a long-term distributed architecture
target, not as a result. Future artifacts must distinguish addressable,
materialized, updated, and spiking cells; dormant or procedurally described
cells do not count as active scale. The current memory/throughput bounds and
the event-driven sharding plan are in
`docs/research/100-billion-cell-architecture.md`.

The three-factor path now also supports genuine developmental training.
Previously dormant fitted GLIF5 cells can be recruited in deterministic random
or layered-sheet birth order. Sparse recurrent synapses first overgrow, collect
local pre/post eligibility evidence during training, and are then selected by
activity or a matched random ablation. Optional postsynaptic activity scaling
and post-pruning incoming-strength conservation provide the homeostatic
condition. This state is checkpointed as cell order/activity and structural
synapse arrays; it is not post-hoc pruning of a copied readout. The frozen
384/1,536-cell primary gate failed its predictive criterion; an unchanged
6,144-cell diagnostic still showed state-rank growth and healthier selected
structure, but staged learning remained worse than full-size-from-start.
Exact results are in `docs/developmental-growth.md`.

The same cell circuit drives mini-swe-agent through `HumanCellModel`. A
frozen, instance-specific episodic checkpoint completed the SQLFluff 1625 dev
task in seven cell-generated shell actions and passed the official SWE-bench
evaluator (1/1 resolved). This proves the end-to-end cell interface, not
held-out software-engineering generalization: that checkpoint was grown from a
public solution trajectory for the same instance.

The official Gemma 4 12B QAT Q4_0 development baseline ended after its full
100-action allowance with `LimitsExceeded` and an empty submission, so that
single instance scores 0/1. It is retained as an honest failed baseline, not a
headline comparison.
