# Neutral document to Python development session

Public, repeatable development workload. It does not spend an adjudication or
open R5/R6. This is the smallest integration in the balanced session plan.

Observed gap: neutral document memory has never driven a real Python edit;
the old action bridge pins an answer-supervised document checkpoint.

Hypothesis: a persistent neutral reader plus the existing learned occurrence
binder can acquire two action demonstrations, use a newly ingested fact in a
renamed Python repository, and retain earlier facts and the action schema.

The seed is empty. Both arms see the same two batches of paired three-token
sentences, one batch of two training facts, and an unrelated document. Only
treatment consolidates. Four delayed questions test both directions of those
facts. Two independent repositories then receive one first attempt each,
followed by one explicitly teacher-authored successful transition apiece.
Both arms are offered the demonstrations; NO_UPDATE retains its seed. A fresh
fact batch follows action learning. Two renamed repository tasks test transfer,
then the four old questions and two old code tasks test retention. Unsupported
knowledge, duplicate anchors, and conflicting facts test no-action. A layout
variation is retained as a separate diagnostic, whether it succeeds or fails.

Each repository contains executable Python configuration, an entry point, and a
decoy. Evaluator-only expected output and intended changed path never enter
inference. The entry point executes before and after edits; scoring also checks
all other files and the materialized workspace. Source documents are absent
from action requests. Literal replacement and a learned lexical offset are the
declared action scope; this is not general Python synthesis or autonomous repair.

Controls: same-seed NO_UPDATE; treatment with core, memory retrieval, action
schema, or propagation disabled; an explicitly host-programmed exact fact table
and literal-edit reference. Report language, code, retention, no-action, teacher
exposure, checkpoint lineage, simulation work, stored bytes, time and memory
separately. All first attempts are recorded; teacher repairs never count as
learner successes. No feedback or demonstrations are supplied on transfer.

Initial budget: two motor demonstrations, at most three fixture/implementation
diagnosis iterations, ten minutes per session, ten seconds per Python execution.
Success for this narrow slice requires delayed recall and executable transfer
with update advantage, old-skill retention, preserved decoys, and the predicted
causal-control failures. Report failures without changing this criterion.
