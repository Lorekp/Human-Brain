Status: prospective development return, 2026-09-06. Cost and acquisition unrun.

single return to the persistent document/action workload. Its authored answer

whether the existing local writer/query dynamics can learn useful continuous

## Fixed learner and teaching boundary

Replace the retired recurrent output in LocalMemoryLearner with PhaseContextLMS.
Keep seed 733, writer hidden/key/value sizes 64, input/query size 32 and the
96-neuron context consisting of query activity and retained-memory readout.
The learner owns frozen 258-by-32 document/query byte codes, identical to the
old seed-735 embedding draw. Raw bytes followed by terminator 256 are the only
input encoding. No fabricated output embedding or old decoder compatibility
branch is part of this contract.

The output has CPU float64 potentials, a supplied three-phase neuronal clock
and generic phase-by-all-context gating. Every teacher step updates all 257
output neurons with rate 0.01 times their pre-update one-hot-minus-potential
residual times local presynaptic activity. Its pre-update context-neuron signal
uses the active phase's current output synapses and the loss-sign residual;
this is declared instantaneous weight transport, not history backpropagation.
Average the three signals in float64, validate conversion to the upstream dtype,
then apply the existing writer/query local traces once and retire them.
Fresh zero output weights initially transmit zero upstream credit; this is
part of the actual rule, not grounds for an initialization intervention.

Keep tagged, aggregate, writer_maps_frozen, frozen and writes_disabled controls
with matched initial tensor values. Fixed input codes never learn. All slow
parameters remain fixed during answer-free ingestion. A genuine read-only
generation precedes every correction; the caller then offers two target bytes
and EOS. No execution feedback enters these corrections. Limit generation to
two bytes plus its EOS/cap decision, without output masks or forced successful
stopping. Reject teacher values of any length other than two before any query or update.

## Frozen roster and schedule

TRAIN values are `aa,ab,bb,bc,cc,cd,dd,da` on the eight available key identities
`k00` through `k07`. Every character is taught in both output positions. Use
the existing private seed-733 authoring procedure: 256 groups of four episodes,
each independently sampling two distinct keys, two distinct TRAIN values and
one queried key. Their raw records are `Record kNN has value vv.` and the
question is `What is the value of kNN?`. The same schedule serves all five arms,
1,024 sequential lessons each. Save and hash the whole schedule before fitting.

The twenty final checks per arm are:

- Eight fit questions across four two-record memories holding TRAIN assignments.
- Four new-value checks across four separate memories: `(k00=ac,k01=ca)`, its
  swap, `(k02=bd,k03=db)`, and its swap. Query `k00,k00,k02,k02` respectively.
  Identical questions therefore require different outputs from retained state.
- Four delayed checks reuse those exact novel snapshots after 32 unrelated
  query reads each, with no correction or source reingestion.
- Four interference checks append the same three unrelated records on
  `k04,k05,k06` with TRAIN values to separate copies of those novel snapshots.

This retains twelve memories per arm: four fit, four novel, four interference.
Values `ac,ca,bd,db` are withheld from this integrated TRAIN, but their character
combinations have already been exposed in development. Novel assignments are
not fresh adjudication. No final labels train the learner. Source-free workers
receive only model/memory tensors and case ID, memory ID, query bytes and delay
count. They do not invoke roster authoring or receive documents or targets.
This is a checked routing boundary, not an operating-system secrecy sandbox.
