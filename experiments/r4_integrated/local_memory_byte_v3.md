# Local memory/byte v3: equivalent validation return

Status: prepared 2026-09-06; cost and acquisition unrun.

The [v2 configuration](local_memory_byte_v2.md) remains closed under its own
cost decision. Its complete-lesson profile identifies finite validation as a
substantial cost. This successor tests one implementation hypothesis: replacing
the existing Boolean finite predicate with an equivalent NumPy predicate over
a temporary CPU float32/64 view reduces complete-workload cost enough to admit
the unchanged local learner. Other dtypes/devices/layouts retain Torch behavior;
the optimization does not remove checks or change model arithmetic. The
[measured implementation result](../../docs/research/local-finite-validation-development.md)
is engineering evidence, not cost admission or acquired capability.

## Fixed scope and evidence

Every v2 learning equation, mode, roster, supervision clock, seed, dimension,
learning rate, exposure count, prediction cap, source-removal rule, control and
success requirement remains unchanged. Its intentionally zero unused frozen
writer credit and host-authored occurrence-motor scaffold remain disclosed.
No LLM, new curriculum, answers at ingestion, global optimizer, extra practice,
learning from execution or autonomous recovery is introduced. The full
[v1 workload contract](local_memory_byte_v1.md) supplies the inherited detail.

The five arms each receive 1,024 sequential lessons; teaching schedule SHA-256
remains `5aa2b390194d28f8f58e8f9cc8ce0c0f1e0b6721ba848177101448b5564a14ac`.
The final source-free worker answers twenty checks per arm from detached saved
state, followed by 100 real actions and two common motor demonstrations. Require
tagged 8/8 fit, 4/4 fresh-value, 4/4 delayed and 4/4 interference exact executed
answers, with strict fresh-value superiority to writer/maps-frozen, frozen and
writes-disabled. Aggregate superiority remains a separate tag-specific claim.
Generated bytes come from the local neuronal decoder; host motor matching prevents a neuron-only
action-selection claim. This cannot pass the general integrated or protected
coding gates.

## Harness identity and unchanged budget

The new shared harness extracts orchestration once; frozen v1/v2 files remain
unchanged. The thin v3 wrapper supplies an immutable experiment identity. Its
factory, lesson, worker, action child, cost formula and admission all use that
same explicit identity and the one fixed workload. No CLI workload/policy hooks
are added. The source manifest includes the harness, wrapper, recipe, frozen
predecessors and full implementation closure. Packages include Torch and NumPy;
native library, source revision, schedule and exact launcher command stay bound.
Use a fresh admission and fresh output directories; do not reuse v2 artifacts.

Print only completed lesson count and elapsed seconds after every 128 completed
episode indices during acquisition. These lines introduce no extra evaluation,
score-dependent control or policy change; their cost remains in the run budget.

Allow one disposable cost phase of at most 900 seconds total and, only after a
passing cost decision and saved-only audit, at most one 900-second acquisition.
All attempts count within their phase. Peak limit remains 2,048 MiB, including
conservative parent-plus-worker and sampled live-tree accounting. Discard all
engineering/cost weights. Native preparation and launch use the same environment.

The cost phase still measures four longest lessons per arm, full-length capped
prediction, final ingestion/serialization, fresh-process queries, all actions
and finalization. Keep the original conservative estimate exactly:

```text
2 * sum_arm(1024 * (maximum complete sampled lesson + capped prediction))
  + 2 * (outer cost elapsed - sum all sampled lessons) + 30 seconds
```

The extra capped prediction remains additive even when an actual first attempt
already reaches its cap. `project_cost(SPEC, report, launcher)` recomputes the
estimate; `validate_cost_launch` binds the observed owned processes and exact v3
command. Acquisition is forbidden unless projection <=900 seconds and memory
<=2,048 MiB. Cost rejection, nonfinite learning, failed fit or missing useful
advantage closes v3, with no automatic new seed, rate, practice or relaxed margin.

## Launch

Root prepares an `engineering_qa` admission using `SPEC.config`,
`harness.sources(SPEC)`, revision, package/native identity and the schedule hash.
After source review and freeze:

```powershell
$env:HUMANBRAIN_NATIVE_CACHE = Join-Path (Get-Location) '.native-cache'
$env:HUMANBRAIN_DEVICE = 'cpu'
$env:OPENBLAS_NUM_THREADS = '1'
$env:OMP_NUM_THREADS = '1'
$env:MKL_NUM_THREADS = '1'
$v3Admission = (Resolve-Path '.pytest-tmp/local-memory-byte-v3.cost-admission.json').Path
$v3Hash = (Get-FileHash -LiteralPath $v3Admission -Algorithm SHA256).Hash.ToLowerInvariant()
$v3Revision = git rev-parse HEAD
$v3Output = Join-Path (Get-Location) '.pytest-tmp/local-memory-byte-v3-cost'
./experiments/r4_integrated/run_source_absent_memory_byte_v1.ps1 -Seconds 900 -MaxMiB 2048 -LogBase $v3Output -ChildArguments @('-X','utf8','-m','experiments.r4_integrated.local_memory_byte_v3','cost','--output',$v3Output,'--admission',$v3Admission,'--admission-sha',$v3Hash,'--revision',$v3Revision)
```

On passing the audit and recomputed projection, write an `admitted` record with
the same identities and hash-bound completion/launcher paths plus recomputed
`projected_seconds` and `peak_upper_mib` under `cost`. The acquisition command
uses `run`, this new admission and fresh `local-memory-byte-v3-run` paths, with
the same 900-second and memory limits. Publication must distinguish first
attempts, teacher corrections, executable success and each control's failures.
