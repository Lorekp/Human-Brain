The next learning decision should address **relevance of learned sequence
predictions to the actual public situation**, rather than strengthening recall
through another gain, more repetitions or an exposed-task gate. The
[implemented design](dendritic-request-binding-v1.md) supplies the new branches
with a 32-byte output prefix and raw request features. Actual files and feedback
reach the inherited prior, but not the new apical request population. Moreover,
branch support outranks that prior categorically. This creates a concrete
architectural possibility: a learned prefix/request match can dominate despite
a changed workspace or consequence. The observed failure does not prove this
possibility was the dominant cause.

One coherent direction for design review is to make the same locally learned
sequence cells bind their predictions to input-derived public observation
context as well as instruction and prefix. Source and answer observations
would continue to teach those acting cells, with all observed symbols counted;
no task ID, correct address, semantic parser or backward error transport should
supply relevance. A complete design must explain how that context becomes
selective without another broadly overlapping readout. Merely adding raw
features would not establish synonyms, variable binding, long-range structure
or composition. This is a bounded next decision, not an implementation
selection or a claim that the present aggregate results identify its solution.
