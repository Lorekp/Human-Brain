## Windows ownership contract

For a supported local NTFS path, use `ctypes.WinDLL("kernel32", use_last_error=True)` with explicitly declared argument/result types. Open the final payload with `CreateFileW`: `GENERIC_READ`, `FILE_SHARE_READ` only, `OPEN_EXISTING`, `FILE_FLAG_OPEN_REPARSE_POINT`, and null security attributes. There must be no write/delete access on the owned handle and no inheritance into action children. Windows enforces incompatible sharing against existing handles and future opens; omitting write sharing also conflicts with an existing writable mapping. Omitted delete sharing prevents ordinary deletion/rename. This is stronger than marking the file read-only. [Microsoft CreateFileW contract](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew).

Validate that the handle identifies an ordinary disk file, not a directory, reparse point or delete-pending object. Query its size and `FileIdInfo`; bind the volume serial and complete 128-bit file identifier. That pair identifies the open file independently of the path. Keep the handle open continuously. [Microsoft FILE_ID_INFO contract](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_id_info).

For the first implementation, explicitly select the optimized backend only on Windows fixed local NTFS volumes with the required APIs available. Other platforms or unsupported filesystem capabilities use the original full-byte verification path, recorded as `verify_each_boundary`. They do not use advisory locks or a timestamp cache as an equivalent guarantee. Once a supported backend is selected, sharing violations, failed identity calls or a broken lease are integrity failures, not reasons to silently fall back and accept the same entry.

The guarantee concerns ordinary file operations within the repository's existing process/filesystem trust boundary. It does not claim protection against privileged raw-volume modification, kernel failure, injected code closing the process's private handles or physical storage corruption. No file-sharing scheme can infer arbitrary hidden bit changes without reading bytes. Fresh independent verification remains mandatory.

## Publication, reuse and close

1. Keep the existing private snapshot, exclusive temporary-file creation, `torch.save`, flush/fsync, temporary-file SHA and size guard. This preserves the existing serialization-to-hash contract.
2. Rename the temporary file to the unique final route name. Before the boundary can refer to it, acquire the read lease and hash **through that held handle**, in bounded 1-MiB chunks. Require equality with the temporary-file digest and exact byte count. This catches replacement or in-place changes during the rename/open handoff. If the lease cannot be acquired or equality fails, leave the intent unresolved and HEAD unchanged. Close partial handles; retain diagnostic files as before.
3. Retain a frozen private entry containing expected path, digest, size, file identity and handle owner. The temporary hash and the leased hash are two real passes per new version; do not describe them as a single physical read. It is the final leased authentication that happens once, followed by reuse.
4. On an eligible `_boundary` payload check, retain all existing schema/digest/size checks. Require a live lease from this store, exact expected name/hash/length, unchanged held-handle identity/size, and a newly opened read-only path handle identifying the same file. Run `_relative` and reparse/path containment checks as before. Close this temporary identity handle immediately. This catches changed directory/path resolution; a matching timestamp is never sufficient. Do not read payload bytes again. The owned handle continues to block writes and replacement of its file object, including through another hard-link name.
5. Immediately before final boundary/HEAD publication, recheck the payload lease identities and resolved names used by the new boundary. Preserve final live-model/tape seals, `_actors`, `_binding` and `_frontiers` checks. This adds small metadata operations rather than removing mutable-state guards. Publication remains copy/write-only after successful checks under the existing synchronous owner contract.
6. Add idempotent `store.close()` and context-manager support. Explicit close marks the store closed and rejects subsequent operations; do not close and silently reacquire a cached entry. The future runner calls close in `finally`, after recording failure or completion, without deleting payloads or intents. OS process termination releases handles. Keep all published versions leased until close: V7 would have required 30 retained file handles, not one per boundary. If handle/resource limits prevent acquisition, fail the transaction before HEAD publication; do not evict protection silently.

No writer remains open while the lease is acquired. Plain independent readers can coexist. Acquiring the final lease before rename would prevent the rename, so that ordering is deliberately excluded. The second hash is the minimal handoff repair rather than a new writer-wrapper abstraction.

## API and fresh checks

The helper exposes a small internal `PayloadLease.open(path, expected_sha256, expected_bytes, work)`, `verify_path(path, work)` and `close()` interface. It retains no tensors and returns authenticated byte metadata, not a deserialized object. Use `ReadFile` on the owned handle for initial hashing; this avoids ambiguous double ownership between CRT descriptors and native handles. Handle IDs are process-local and never serialized as evidence.

The checkpoint integration needs a private `_payload_file(row, *, fresh=False)` seam replacing only the payload-specific `_file` call in `_boundary`. Cache misses retain `_file`; new publication installs a lease only after its handoff authentication. Thread `fresh_payloads` through `_boundary`/`inspect` for explicit callers. `restore_into` requests fresh checks at both existing inspection points and retains its current authentication of the exact bytes passed to `torch.load(io.BytesIO(raw))`. A new `open()`/independent inspector, with no map, performs full hashes. Source files, manifest, journal prefixes, mutable workspaces and executor captures never use these payload leases.

Ordinary public `inspect()` on the owning store remains checked through enforced ownership and path identity; an explicit fresh inspection remains available. The lifecycle is single-threaded and synchronous like the present store. No concurrent commit, shared lease map or inherited child ownership is introduced.

## Honest accounting

Keep charging existing `checkpoint_hash_bytes_read` and `checkpoint_file_hash_passes` for actual streamed data, including the additional handoff authentication. New counters should name actual lease acquisitions/releases, retained/peak handle count, metadata queries, temporary identity opens, authenticated versions, successful reused checks, and fallback full checks. Report skipped historical payload bytes separately as counterfactual work avoided; never add them to actual read traffic. Failed partial reads/opens must charge work already performed.

The implemented counter names include `checkpoint_payload_lease_acquisitions`, `checkpoint_payload_lease_releases`, `checkpoint_payload_live_handles` (a gauge), `checkpoint_payload_peak_handles` (maximum), `checkpoint_payload_metadata_queries`, `checkpoint_payload_identity_opens`, `checkpoint_payload_authenticated_versions`, `checkpoint_payload_lease_reused_checks`, `checkpoint_payload_full_hash_checks`, `checkpoint_payload_fresh_hash_checks`, `checkpoint_payload_prepublication_checks`, and `checkpoint_payload_avoided_hash_bytes`. Capability/volume queries, read calls, allocated hash-buffer bytes and close calls have separate actual counters. A prepublication metadata recheck is not credited with avoided hash bytes because no corresponding old hash call was removed there.

`checkpoint_payload_lease_open_attempts` and `checkpoint_payload_identity_open_attempts` increment before their native opens, so unsuccessful calls remain visible. Successful-handle setup is inside cleanup protection; even a bookkeeping exception cannot bypass the native close attempt. Closing the store attempts all owned releases before propagating the first cleanup error.

Hash scratch stays bounded by the existing 1-MiB block policy. Lease entries are small Python/native objects whose overhead is not tensor memory; record handle peaks without inventing exact RSS. Old `_file` newline scans of arbitrary tensor bytes disappear on eligible reuse too. The source/timing scopes must state that no journal-frontier or live-neuron validation was removed.

For B noninitial boundaries and constant per-route payload size S, the previous two-route begin+commit path reads roughly `4*B*S` payload bytes. The new path instead adds one protected handoff read per newly written version plus metadata-only reuse; the original temporary-file hash remains. This describes source work, not a latency prediction. The exact upcoming trace supplies differing file lengths, reused checks and actual timings. Independent audit and fresh restore still pay full authentication.
