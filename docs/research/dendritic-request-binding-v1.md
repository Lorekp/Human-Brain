# Paired dendritic request/prefix predictor

2026-09-07. Root-selected source implementation after source/math review. No
model, feature, checkpoint, corpus, testcase or experiment was evaluated for this
selection. This is one falsifiable broader-loop candidate, not established
language understanding. It completes the missing signal origins in
`docs/research/persistent-ordered-context-learning-review-v1.md`.

## 1. Concrete choice and what changes

Use **byte/EOS cells with multiple learned basal/apical branch pairs**. Basal
contacts recognize ordered raw-prefix activity. Apical contacts recognize a
held, input-derived request population. Each branch predicts the byte column to
which its cell belongs. There is no new dense output matrix, recurrent random
encoder, whole-example gain, supplied sequence ID, or latch that commits to a
previous answer. All output columns participate at every decision.

Two possible fixed forward rules were considered:

* **Pooled:** a cell qualifies if any basal branch and any apical branch match.
  Reject this: basal context from one learned occurrence and request context
  from another can combine without ever having co-occurred. Adding their counts
  also lets common activity buy an arbitrary amount of output preference.
* **Paired:** a conditional prediction requires the basal and apical compartments
  of the **same branch** to match. Recommend this. It binds the two actual
  co-active inputs through local contacts. It does not guarantee semantic
  equivalence or forbid different requests from matching the same contacts.

This is deliberately a finite-order dendritic predictor rather than a claim to
implement the complete HTM theory. The basal state is an explicit 32-symbol lag
population, not an unproven compressed recurrent state. Learned nonlinear
contacts change which ordered prefixes predict each output. That directly
avoids presenting another fixed reservoir plus linear readout as new binding.
The prior dense-readout overlap and V6 similarity-collapse evidence still apply
as failure risks, not proofs that these new contacts will succeed.

## 2. Fixed inputs, identity and stream state

Output identities are raw bytes0..255 and EOS256. BOS257 is an input-only symbol.
There are V=257 output columns, M=16 cells per column and D=4 branch pairs per
cell: 4,112 cells and16,448 branch pairs. These are proposed fixed capacities,
not values fitted to V6. Different cells/branches represent different contexts
for the same output byte; no journal group supplies their identity.

**Basal input:** initialize a stream with BOS at lag0 and31 empty lags. The
held population is `X[l,s]=1` exactly when lag l contains symbol s, for
`l=0..31,s=0..257`; empty lags activate nothing. Dimension8,256, at most32
active cells. After an actually observed or generated byte, shift lags and
insert that byte. EOS ends the stream. The cell input is the activity **before**
the current symbol. A branch never sees a future byte to predict itself.

One stream is a source document or a payload. Reset at these public byte-stream
boundaries; do not reset at host-detected identifiers, clauses or answer spans.
The 32-lag limit is real: history beyond it cannot affect new branch matching
through this population. The old prior still has its declared context access.

**Apical request input:** construct Q once from the entire actual request of
0..256 bytes, and hold its exact activity throughout a response and any source
observation associated with that request. Use three disjoint binary channels:

1. U:256 byte-presence cells. Set U[b] when byte b occurs anywhere.
2. G:258² ordered adjacent-pair cells. Form `[BOS, *request, EOS]` and activate
   each observed ordered pair. This retains start/end pair information without
   knowing words, operators or roles.
3. P:8×256 coarse-position cells. Byte at absolute position i activates
   `P[i//32,b]`. No normalization by request length changes bin boundaries.

Q has68,868 logical cells and at most769 active cells. Duplicate features are
binary presence, not repeated votes. An empty request activates only its
BOS/EOS pair. A source admitted without a request has Q absent, distinct from
the empty request. No task ID, kind-specific answer cue, correct memory index,
semantic parser or pretrained representation is added. Raw request bytes and
length remain in custody. The feature construction is a fixed IO prior and
must be counted, not described as learned language.

This representation shares byte pairs across some wording changes and preserves
some ordering/position. Synonyms with different bytes have no supplied semantic
similarity. Word reorderings can preserve the same pair set, and insertions can
move positions across bins. Those collisions and discontinuities are explicit
generalization limits. The three compartments prevent a match on common
unigrams alone from qualifying as a request match.

All existing raw workspace and feedback inputs remain available to the frozen
prior and action heads. Q does not pretend to encode those bytes. In particular,
the new conditional branch can dominate despite changed feedback if its request
and generated prefix still match; feedback-dependent repair is not supplied by
this mechanism. That is a broader-loop limitation to report, not hide with an
executor correction.

## 3. Branch forward equations

Every branch has one basal compartment and three apical compartments U/G/P.
Each potential contact stores a fixed presynaptic index and a uint8 permanence
`p in {0,1,2,3}`. It is connected iff `p>=1`. The compartment count n marks its
allocated prefix of contact slots; integer0 is not an address sentinel. Basal contact capacity16;
apical capacities8/16/8. Contacts are unique within a compartment.

At compartment creation, choose `n=min(capacity,number_of_active_inputs)`
distinct active inputs with this exact stable rank. For global branch index j
and compartment r=0..3, set `identity=4*j+r+1` and
`base=(seed+0x9E3779B97F4A7C15*identity) mod 2**64`. For each active input k,
let `z=(base+k) mod 2**64`; apply the SplitMix64 finalizer:
`z=((z xor (z>>30))*0xBF58476D1CE4E5B9) mod 2**64`,
`z=((z xor (z>>27))*0x94D049BB133111EB) mod 2**64`, then `z xor (z>>31)`.
Stable bottom-up mergesort orders `(z,k)`; take the first n, then store their
indices in increasing order using the same explicit sorting algorithm. Seed733
is the default; valid seeds are integers in[0,2**63). No Python randomized hash
or ambient RNG is used. No target string, episode, success grade or semantic
parser keys sampling. Count mixing, comparisons, entries and copies. Set n permanences to1,
making one observed association immediately usable. The contrast with
subthreshold initialization is declared; there are no hidden extra repetitions.

Store `theta=ceil(3*n/4)` at creation. Empty compartments have n=theta=0.
For a nonempty compartment r:

`m_r = sum_contacts 1[p>=1] * input[index]`

`active_r = 1[m_r >= theta_r]`.

The threshold uses initial potential-contact count, not remaining connected
count; disconnecting contacts must not automatically lower the threshold and
make a failed predictor easier to activate. Once created, contact indices and
thresholds do not grow or recycle in this minimal candidate. An incompatible
new context can recruit a new branch until capacity is exhausted.

Basal prediction is `B=occupied AND n_B>0 AND active_B`: an unused/empty basal
branch is inactive despite a zero threshold. A branch with apical contacts qualifies as
`A = Q_present AND AND(active_r for each nonempty apical compartment r)`.
At least one apical compartment must be nonempty; an absent Q cannot predict
conditionally by vacuous truth. Conditional activity is `J=B AND A` on the
same branch. All these are explicit input applications, sums and threshold/AND
cells. Sparse indexing selects actual afferents; it does not look up an answer.

## 4. Explicit autonomous byte/EOS competition

For output byte b, form categorical support:

`class_b = 2 if any branch of b has J; else 1 if any has B; else 0`.

Let `v_b` be the frozen existing reader's actual byte/EOS potential for the
same request, observation, tape and **own current generated prefix**. Evaluate
that prior once per decision using the existing arithmetic, including all
eligible memory addresses. Do not run a separate complete old prediction and
reuse its incompatible later prefixes.

Use exact lexicographic competition on the two current components `(class_b,v_b)`:
higher class first, then higher frozen potential, then lower byte identity.
Do not compress the prior into a saturating scalar and claim exact ranking.
For competing leaves i<j, define `dc=class_i-class_j`, `dv=v_i-v_j`,
`g=1[dc>=1]`, `e=1[dc==0]`; i wins iff `g OR (e AND 1[dv>=0])`.
Class equality can be two threshold comparisons with an AND. These are explicit
fixed threshold/gating cells, not a host semantic tie breaker. Reject nonfinite
prior values or subtraction overflow before publication. A fixed ordered
257-leaf tournament retains every byte and gives globally lower-index ties.
Every leaf's prior is evaluated; this is not a selected answer shortlist.
A byte with many matched branches receives no extra votes. No learned confidence
or normalized sequence probability is claimed from this discrete support class.

**Ambiguity:** multiple predicted bytes are resolved by the frozen prior, then
the fixed tie rule. **No prediction:** class0 for all, so the old prior decides.
**EOS:** participates exactly like the other256 outputs, with learned basal and
apical contacts; it is not forced because a prediction is uncertain. Preserve
the128-byte output bound: the final decision can emit EOS; otherwise report
LIMIT without appending another byte. No task-correctness test chooses stopping.

For source-only next-symbol predictions with no response prior, use `v_b=0`
for every b in this same competition function. That is a declared absence of
the action-conditioned prior, not a second learned predictor. There is no
requirement to construct an old query/model for every externally arriving
source byte. The new cells, branch arithmetic and subsequent local updates are
the same cells used to generate action payloads and reading answers.

The stronger categorical conditional priority is itself a falsifiable forward
prior. It can select an irrelevant learned sequence more decisively. It does
not claim numerical parity once a new branch is active; at an entirely empty
new bank it preserves the old prior's byte ordering.

## 5. Observed-symbol learning, without reverse credit

Separate three events: prediction before a symbol, arrival of that symbol,
and permitted synaptic publication. A generated byte only advances basal state;
it is not automatically a correct training target.

**Selection for learning:** after an external/teacher symbol b arrives, its
fixed sensory byte column receives proximal activation. Select one branch in
that column from held pre-arrival activities. With apical learning, eligibility
priority is joint match, then basal match with no apical contacts, then unused
allocation. Rank only inside that category: a strong incompatible basal match
must not hide an attachable one. Source-only selection uses basal matches
regardless of apical contacts. Within a category choose larger basal count,
then larger apical count, then lower branch identity. Its scalar local-WTA
simulation counts sums, signed differences, thresholds and Boolean gates
separately from the257-byte tournament. Structural allocation counts its own
least-used-cell and first-unused-branch scans. This chooses among representations of
the *observed byte*. It supplies no correct hidden event, source span or episode
label. Unlike V6's input-only owner preparation, the byte's arrival legitimately
determines its sensory/output column; this signal boundary must not be mislabeled
as target-free prediction.

If a basal match exists but no matching apical association exists, attach
apical contacts to a matching branch that has none. If all matching branches
already have incompatible apical contacts, allocate an unused branch in the
same output column. If no basal match exists, also allocate an unused branch.
Choose a cell with the fewest used branches, then lower cell/branch index. On
column exhaustion, skip the new association and count it; do not evict a prior
branch or silently fit an incompatible one. Existing matched branches can still
receive their specified reinforcement. Source-only learning can select a basal
match regardless of its apical association and leaves its apical state intact.

**Local positive adaptation:** for each existing contact on the selected
compartment, use its own pre-arrival input x and actual selected postsynaptic
activation1:

`p <- clip(p + x - (1-x), 0, 3)`.

Promote uint8 permanence and Boolean activity to signed int16 before these
operations and the `p-x` rule below; clamp before casting back. Counts and class
differences use signed int16/int32. A clamp after uint8 underflow is invalid.

Newly created contacts start at1 and are not incremented again on that same
offer. Reinforce selected basal contacts on every permitted observed-symbol
offer. Reinforce/create apical contacts only on declared request-conditioned
correction offers, when Q is present. A pure source observation updates basal
contacts only. If later paired input is admitted as apical learning, that would
be a separately counted change to the exposure contract.

**Own-cell false prediction:** on a request-conditioned correction offer,
each previously jointly active branch in another byte column receives
`p_A <- max(0,p_A-x_A)` on its active apical contacts only. Its own predicted
column did not receive the arriving sensory byte. This is a local prediction
confirmation/absence signal; it is not a derivative of the final hard winner
or backward transport through basal/request encoding. Do not punish its basal
sequence contacts, which may predict a valid transition in another request.
Do not apply this apical decrement to source-only or self-generated symbols.
No false-basal decrement is selected, because an unobserved alternative next
source byte need not be an invalid language continuation.

All false-prediction sets and positive selections come from the same held
pre-offer stage. No post-update emission manufactures the teaching signal.
Positive and negative effects on different contacts are staged before advancing
the observed byte into the lag population. Contacts are bounded, but there is
no promised monotone global loss, no one-pass semantic convergence, and no
proof against interference among matching branches.

This is not a new dense output rule: the observed byte teaches its own proximal
column and those cells' local predictive contacts. No `W^T error`, hidden-state
target, responsibility from the eventual hard choice, or hand-expanded Jacobian
teaches an upstream population.

## 6. Same actor, exposure and atomicity

One reader owns this bank and the frozen old prior. The existing combined actor
still proposes operation/path/span plus the new byte payload, executes the
actual proposal, and only then accepts a declared correction or acknowledgement.
Old reader B/C/U/codec/router and existing event contents remain fixed during
new branch learning. Existing direct-local action-head correction can continue
under the same enabled flag; no separate fitted executor supplies actions.

The pending response seals request/Q, raw observation, tape/model identity,
actual selected bytes, prefix histories, prior potentials and branch decisions.
Correction stages begin with the same Q and output-BOS state, then consume each
already offered target byte and EOS causally. These are additional forward
steps on earlier teacher prefixes, explicitly counted; they are not claimed to
be the earlier free trajectory. A correction must fit the actual response cap.
All target offers are counted, including those after capacity exhaustion.

Source admission pairs ordinary tape writes with one source-BOS stream and one
pass of the arriving document bytes plus EOS. `n+1` source offers include the
first byte after BOS and final EOS; empty source has one EOS offer. Construct
the prediction before admitting each next symbol to this population. Holding
the complete raw file in host IO is not permission to feed its future bytes
into these predictions. Existing old tape ingestion remains the same ordinary
association mechanism. No old document is re-presented to initialize branches.

Online can learn basal contacts from fresh source and basal/apical contacts from
declared corrections. Matched disabled receives the same offers but publishes
neither contact changes nor allocation advancement; ordinary factual tape
association writes remain enabled in both routes. Instruction encoding alone
is not another source-teaching pass. Actual feedback can be admitted as a
separately counted basal-only stream; its raw bytes are neither correct code
nor a task-success reward. Keep source, feedback, correction, generated and
boundary-symbol counts distinct. No new corpus or exposure schedule is chosen
by this design.

Stage an entire bounded document or correction privately, including contacts,
occupancy and allocation state. A disabled stage computes proposals against
its unchanged private bank, without teaching later symbols from earlier disabled
updates. Before any live copy, validate all stages, pending identities, lengths,
finite prior currents, contact uniqueness/ranges, thresholds and action-head
proposals. Hold the tape returned by ordinary ingestion privately until the
branch stage also validates. Publish through copy-only commits after all
fallible checks. Prepublication validation failure leaves the live model, tape
and pending response unchanged. Later journal IO failure after live commit
cannot roll that commit back: preserve the failure and stop further admission.
Journal each successful transaction before admitting the next; checkpoint at
safe idle boundaries under the shared persistence policy. Ordinary acknowledgements clear custody without
pretending the emitted bytes were verified teachers.

state is not recoverable from a missing checkpoint. Do not fit/reconstruct its
gains from journals. Add an initially empty dendritic bank; retain every old

## 8. Falsifiable integration expectations and limits

The intended change is specific: newly observed source transitions shape the
same basal predictor later used in payloads; paired apical contacts associate
actual request features with observed byte transitions; false request predictions
can lose apical support without globally changing every owner's parameter.
The mechanism may therefore reuse local syntax and disambiguate some related
instructions with fewer answer corrections than a full-example store.

It can also fail in recognizable ways: unrelated requests satisfy the same
sampled compartments; source-only branch predictions dominate a useful prior;
new synonyms lack shared contacts; negative apical updates erase legitimate
branching; finite-order contexts confuse nested or reordered programs; feedback
does not change a dominant joint prediction; or capacity saturates. Capturing
a longer coherent wrong answer would not count as resolving relevance.

No claim of systematic composition, variable binding, learned source selection
or autonomous repair follows from local correctness. Those remain outcomes of
the shared broader workload. This complete proposal is intended to be falsifiable
there, with separately reported acquisition, fresh instructions/combinations,
retention, recovery and raw-experience costs. It proposes neither a theorem of
understanding nor another isolated byte/gain/latch gate.

## 9. Core interface and source accounting

The new `DendriticRequestBinding(seed=733)` owns only the five contact-bank
buffers. `encode_request(raw, work)` builds the held public request population;
`encode_prefix(prefix, work)` builds causal newest-first basal activity.
`evaluate(prefix, request, prior, stage=None, work=None)` returns a sealed actual
decision before any observed symbol enters `prepare_observation(stage, decision,
symbol, apical_learning=..., enabled=..., work=...)`. Preparing an observation
consumes that decision once. Source uses absent request and zero prior;
corrections use the held request and the actual inherited prior for each causal
teacher prefix. The actor integration owns response, action and tape custody.

`begin_stage` clones the bank once for a whole transaction. Tensor identities
and bank hashes bind private storage; replacement with live storage is rejected.
Each observed event constructs only selected-row and false-prediction contact
proposals, then advances private storage when enabled. `validate_stage` checks
the whole proposed bank and unchanged live identity before the copy-only
`commit_validated` seam. Strict state loading validates every new field before
copying; a recursive owner load explicitly invalidates old stage revisions.

`decision.record(work)` retains257 signed classes,257 prior currents, the fixed
tournament identity trace and at most four selected compartment counts. Its
new tensor copies cost2570 bytes without a selected branch or2578 bytes with
one. Full16,448-branch match arrays are transient, not accumulated per observed
symbol. Update records preserve the selected branch's at most48 contact indices,
actual input activities and before/after permanences, plus false-prediction
branch identities, counts and proposal digest. This supports local scalar
inspection without claiming that saved compact records reconstruct all omitted
contact gates.

Work counters separate contact applications, local branch selection and
structural allocation from the257-output threshold tournament. Branch selection
counts its candidate scan, two apical additions per candidate and explicit
comparison thresholds/Boolean gates; deterministic sampling counts identity
arithmetic, SplitMix64 operations and merge-sort comparisons/copies. Full-bank
validation and hashing still occur during staged evaluation and validation and
after enabled private changes; their costs are counted rather than hidden behind
an unimplemented cache. Named tensor allocation counters describe the listed
source allocations, not peak RSS or a complete Python/backend allocation bound.
No tests, source observations or correction offers are executed by this source
implementation step; ordinary QA and the shared broader session require their
separately owned release.
