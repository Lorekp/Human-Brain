## Reference provenance and its actual limitations

The independent attribution check covers all72 saved reference attempts. Its
initial history contains the16 documents and12 editing demonstrations actually
observed in session1. Every demonstration is bound to its preceding actual
acquisition action by the saved attempt hash. During session2 it receives only
the two scheduled new documents and12 new editing demonstrations, ending with18
documents and24 demonstrations. No reading-answer table is restored or created.

For each reading, scalar raw-query trigram similarities confirm the recorded
document choice and earliest-index tie rule. The emitted bytes equal the first
boundary-delimited quoted literal from that available document, with the
recorded source hash and span. For each edit, the same checks confirm the chosen
available demonstration, query/source hashes and raw replacement. Its old
literal must occur exactly once in the actual current files; otherwise the
reference emits STOP. Eleven of48 executable attempts choose an old-session
demonstration and37 choose a new-session demonstration. These counts include
failed and repeated recovery attempts, not just successful examples.

The ordinary algorithm has concrete weaknesses despite its stronger scores:

- “Ordinary log name, please.” retrieves the temporary-log note and returns
  `trace` instead of `audit`; “Cold backup region, please.” returns `west` rather
  than `north`. Available relevant facts do not guarantee correct lexical routing.
- “Not testing: which badge?” returns the testing colour `green`, failing the
  negation. “Retries then delay; use /.” returns only `3`; “Debug/normal logs;
  use /.” returns only `debug`. Single-document literal extraction does not
  construct the requested `3/2` or `debug/audit` answers.
- The fresh join edit reuses a numeric retry replacement inside a string join
  and fails. Reusing a fact's demonstrated bytes does not adapt their program
  representation to a new context.

Successful editing is genuinely behavior-scored. In the archive-lookup case,
the reference replaces the fallback value, while the canonical annotation
changes the lookup key. Its alternate patch is accepted because execution
produces the required output and preserves protected files. The evaluation
therefore does not require one author-chosen byte span or patch.

These checks establish attributable conventional retrieval/edit reuse. They
do not establish neural understanding, semantic negation handling or general
program synthesis. The reference's answers must not be inserted into the
neuronal route and relabeled as its learned decisions.

## Freshness and retention

All16 fresh requests differ byte-for-byte from both session1 and current
acquisition requests. The data introduce negated/contrastive phrasing, ordered
answer joins, and combinations such as tuple unpacking, iterator calls, joins,
dictionary defaults and lambda application. The author-assigned construction
labels are unseen in the earlier manifests, and all eight fresh edit structure
labels are new. These labels are judgments, not a proof of distinct linguistic
families: for example, a fronted expiry question retains familiar “how many”
language. Facts and substantial vocabulary remain exposed.

Independent token-set overlap against all previous and current acquisition
requests ranges from0.1364 to0.6667, median0.3693. The new wording and structural
combinations are useful development pressure, but this is neither protected
transfer nor authentic official-exam evidence. In particular, the two short
composed-answer requests and the negated condition are real supported demands;
their failures must remain visible instead of being replaced by easier literal
questions or solved through a host parser.

The eight retention items exactly reuse old-session observations. Their proper
comparison point is the **previous delayed outcome**, not a similarly numbered
current acquisition item. The reference preserves all eight previously correct
delayed outcomes. Both new neural routes begin from the previous online history,
where those eight items already failed, and all eight fail again. This supplies
no evidence of eight newly forgotten skills. Neither session's first-attempt
versus delayed records establish immediate post-correction mastery.

Files reset at episode starts and continue only across the three recovery
attempts. Learned state and memory persist; this is not one continuously edited
software project. Recorded stdout/errors do not enter a new feedback encoder,
so zero recovery does not test an implemented consequence-learning rule.

## Shared next question

The reference demonstrates accessible facts and reusable edit history while
also exposing the need for conditional reasoning, composition and contextual
formatting. The new neural input capacity alone has not produced useful answers.
Coordinate the next source/learning review around **effective local sequence
teaching that transfers to the learner's actual free-generation trajectory**,
as developed in the companion learning review. Distinguish a locally valid
update, a teacher-prefix fit and successful unforced continuation; none implies
the others. Do not infer that another operation-only branch will fix outputs
that fail to terminate or produce the required replacement.

Keep the next pressure broad, with bounded teaching, fresh forms, retained
history and actual actions. Do not rescore these outputs by substring inclusion,
replay this public set until perfect, supply a correct address, or let the
current teacher symbol enter the free prefix. Wrong routing, composition and
feedback use remain unresolved alongside sequence teaching. This is one shared
review priority, not a selected new fit, sweep or architecture queue.
