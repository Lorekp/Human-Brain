## Minimal versioned integration

Add one explicit `direct_python_action_bridge_v1.py` owning the qualified launch
record and the existing small execute/actuate functions. Reuse the current Case,
escape/file-record and motor utilities. Preserve the current executor body and
actuation semantics; change only the child executable/environment selection and
add an immutable execution-identity receipt. A private frozen record can hold
the selected venv path, base path and qualification hashes; pass it explicitly
to the new bridge, with no module-global replacement or general callback system.

The new executor copies `os.environ`, sets the one launcher key, and otherwise
uses the identical argv tail, bootstrap, cwd, raw capture, timeout, return-code,
decode-error, file/materialization and decoy checks. The parent environment is
not mutated. Bind both executable hashes, configuration, Python build and the
qualification receipt in admission and the report; each action records the
selected launch policy/identity and exact executable argv. Preserve measurement
of validation, materialization and execution inside action time. Do not rehash
an entire standard library per action; authenticate that fixed environment at
preparation and completion, with any per-action checks counted inside A.

Create a versioned online runner `local_joint_address_online_v2.py` with the same
four explicit factories, model/rule, roster, seed, lessons and paired logs.
Its three action sites (motor demonstrations, acquisition and final execution)
call the new bridge directly. Reuse unchanged pure utilities, stream classes,
model helpers and cost algebra explicitly. Where frozen v1 functions capture
their old action globals, preserve their small versioned bodies instead of
monkeypatching those globals. Keep all v1 files untouched; use source/AST review
to show that the only action-path difference is the qualified process launch.
No old learner, reference teacher or endpoint is needed to test this seam.
