# Saved literal-update attribution

Selected 2026-09-10 after the bounded repeated-teaching result. Architecture,
learning rule, tasks and the continued learner remain unchanged. This analysis
addresses the unresolved distinction between weak direct teaching and competing
updates. It introduces no teaching, acting, checkpoint decoding, RNG draws or
parameter publication, and makes no counterfactual learning claim.

The [source diagnosis](literal-local-update-diagnosis-v1.md) derives the current
rule. The [saved analyzer](../../experiments/r4_integrated/repeated_teaching_literal_attribution_v1.py)
will reconstruct its actual literal increments from pre-target probabilities
and activities already recorded during the completed run. It separates reading
teacher, editing teacher, scan and public-consequence contributions. Positive
target terms and their opposing probability terms remain separate. No changed
coefficient or hypothetical future path is executed.

Before publication, authenticate the pinned bank, final boundary, source map,
manifest and all journal frontiers. Read probes once, then pair attempts and
teachers in one chronological pass: 510,318,993 journal bytes and 389 rows.
An earlier schema inspection read a separate 1,048,576 teacher-journal bytes;
that is preparation cost, not hidden in this pass. Source and metadata reads
are counted separately. Use only NumPy and standard-library arithmetic in the
analyzer; do not import a learner or invoke the existing full review/restore.

Reconstruct all actual selected literal activities and check their exact source
hashes. Verify coefficients, teacher bytes/EOS, publication gates, scan order,
free prefixes and actual public execution reward. Within each resolution, use
the saved held probabilities throughout; do not simulate sequential updates.
Confirm output-cell increment sums vanish within float64 tolerance.

Project the separate increments at all 35 fixed checkpoint target activities.
Ten sites have full 257-cell currents from actual literal selections at all
five checkpoints. Require reconstructed changes to match every recorded cell,
with absolute tolerance 2e-11, and verify softmax closure. The other 25 sites
support projected currents but lack an independent full-current anchor. Do not
present them as fully verified probability reconstructions. Category currents
add; hypothetical category probability effects are nonlinear and do not.

The predeclared analysis envelope is **600 seconds, 2,048 MiB sampled process-tree
peak and a 16-MiB new report cap**, including authentication and publication.
Keep an 8-GiB free-space floor. Structured failed progress and the outer launch
remain preserved; no automatic retry or learner replay follows a failed check.
The result is published only after complete source/journal authentication and
all closure checks. Output creation is exclusive and fsynced.

Focused QA uses two synthetic arithmetic/receipt tests in the existing decoder
test module, with no learner construction, teacher calls or child execution.
It compares sparse reconstructed updates against an independent dense Torch
outer-product calculation, validates the actual activity hash domain and rejects
changed prefixes/targets/activity hashes. A second fixture checks positive and
opposing contributions and rejection of a wrong non-target cell. These are
implementation checks, not another task-acquisition gate. Record doctor and the
monitored QA receipt before the one saved-data analysis launch.
