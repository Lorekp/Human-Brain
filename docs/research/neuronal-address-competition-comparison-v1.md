# Prospective integrated address-competition comparison

Proposal for root selection, 2026-09-06. This document generates no task data and
authorizes no model, checkpoint, action, test or acquisition. Component QA is not
integrated admission. The [selected mechanism](neuronal-address-competition-v1.md)
and its [learning contract](neuronal-address-competition-learning-v1.md) stay
fixed: initial neuronal competition, one free cursor, and the same persistent
reader's inherited all-address local corrective surrogate at eta .01.

Use one successor comparison to ask whether this mechanism improves complete
executed edits on new contrasts while retaining learned location/operation
behavior and earlier reading. The closed splice-v1 results are exposed
development evidence. Do not rerun its 32 fresh endpoints as a new test set or
promote ordinary component fixtures into transfer evidence.

## Models and fixed acquisition

Propose five arms, in this order:

1. Competitive learned reader and learned action heads.
2. Competitive reader with action-frozen heads; reader still learns.
3. Competitive reader and action heads with all slow publications frozen.
4. Competitive learned model with disabled episodic sensory/key writes.
5. Fresh learned marginal reader and learned action heads, using the current
   no-backpropagation implementation as the mechanism reference.

The fifth arm is useful because publication controls alone do not isolate the
change from marginal emission to commitment. It is a new matched integrated
learning run, not a replay or reuse of a completed marginal endpoint report.
It uses the same local teacher, actual action loop, state schedule and exposure.
Do not introduce an additional temperature, competition-off variant, seed or
alternate teacher into this comparison.

Every arm starts with the same authenticated original v6 reader numerical
tensors and fresh action weights at seed 733. Only the explicitly required
reader-schema/mode metadata differs. Do not resume the learned splice-v1 action
weights or its final reader: doing so would confound different starting histories.
Retain the exact exposed 32 TRAIN tasks from splice-v1, eight fixed rounds with
its original cyclic order: 256 real pre-correction proposals per arm. Reusing
declared TRAIN is intentional; the new evidence is withheld transfer, not a claim
that acquisition tasks were unseen. No extra rehearsal or best-round selection.

Every proposal, including STOP or rejected SPLICE, receives exactly one qualified
actual workspace verification before same-instance correction. Rejecting a
proposal verifies unchanged bytes, never a repaired edit. Supervised bytes and
action labels arrive only afterward; execution grades are not numerical rewards.
The competitive and marginal readers can have identical reader teacher updates
under this schedule while their free actions differ. That is the intended
mechanism contrast, not permission to omit either arm's actual activity.

SPLICE teaching retains its corrected prefix; STOP teaches only the operation
head on the actual proposal's context. Thus different free payloads can legitimately
change later operation learning. Do not claim that all combined weight histories
must match merely because inherited reader teaching is unchanged.

## A fresh 32-task cohort: sixteen paired contrasts

Freeze exact bytes, construction code, package membership and hashes before any
successor predictions. The following allocates four pairs to each factor. Names
and keys must be disjoint from exposed endpoints, but renaming is not the
scientific manipulation. All raw boundaries remain eligible; the same unchanged
raw request enters action heads and reader. No role parser, correct-span mask,
target-key extraction or generated-answer filtering enters neuronal execution.

| Group | Four pairs, eight tasks | What each pair holds or changes |
| --- | --- | --- |
| Document order | Unique target key and a distinct distractor in two literal documents. Reverse their physical tape order between members. | Hold request, files, intended edit and all document bytes fixed; move the correct start to a different physical address. |
| Continuation | Two-document packages with target values `ab`/`ababab`, `ba`/`bababa`, `cd`/`cdcdcd`, `dc`/`dcdcdc`. | Hold request and files fixed within each pair. The first two payload bytes agree, but the correct stopping position differs. Six-byte repetition is beyond the acquisition payload lengths. |
| Value role | Swap two distinct two-byte values between the requested key and another unique key. | Hold request, workspace, key set and document order fixed. Two pairs use two documents ingested before acquisition; two pairs use five documents ingested afterward. This separates delay and interference strata explicitly. |
| Operation/layout | Four SET/KEEP pairs: two replacement pairs, one empty-span insertion pair and one deletion pair. | Members share files and memory, but request operation changes. Use construction-defined held-out layout combinations: spaces/tabs around assignment for replacement; a blank/comment displacement for insertion/deletion. No correctness is inferred by parsing produced code. |

The first three groups contain 24 edited tasks; the last contains four edits and
four explicit STOPs. Total: 28 SPLICE plus four KEEP. Operation/layout exact byte
constructors need source review before roster freeze; every task must be valid
Python and its canonical byte span must be obtained from the authored
construction, not a search that is later reused in the learner. New whitespace
and longer payloads introduce real transfer difficulty; they must not be dropped
if the first outputs are poor.

Each two-document continuation package fits the existing tape capacity even with
a six-byte value. The five-document interference packages use only two-byte
values: each document is 25 symbols including its EOS, so five occupy 125 slots.
Do not accidentally use the longer continuation values in those five-document
packages. Keep every file at most 128 bytes, at most four files, path at most
31 bytes, raw request at most 31 bytes, and payload at most 16 bytes. Literal
payloads already contain any needed Python representation; the host adds no
escaping. The selected longer examples require no new escaping mechanism.

This allocation uses 28 fresh memory states per arm: eight document-order states,
eight continuation states, eight value-role states, and four shared operation
states. The two delay pairs contribute four states before learning. All other
24 fresh states are ingested after acquisition. Each state is ingested once and
retained; endpoint members do not reconstruct or refresh it immediately before
querying. No endpoint supervision or updates occur. The pair contrasts measure
specific invariances; they are not evidence of arbitrary dependency resolution.

## Retention and success

Retain the sixteen original early TRAIN endpoint identities
T00–03, T08–11, T16–19 and T24–27, with their existing tapes. Also retain the exact
twenty old raw reader questions, once before and once after acquisition in every
arm, on twelve separately ingested original document packages. These are exposed
retention controls, not new transfer cases. Report all twenty, including the two
original failures; require preservation of the eighteen prior successes. No
historical delay metadata adds uncounted query traversals.

Freeze the strict criterion before generating any successor output:

- Competitive learned solves all sixteen fresh pairs: 28/28 complete edits and
  4/4 explicit STOPs, with exact required after-files and actual executed output.
- It solves all sixteen retention actions and preserves each of the eighteen
  originally successful old-reader cases at the post-acquisition panel.
- Its fresh edited-task count strictly exceeds each of the three matched
  publication/memory controls and the fresh marginal reference.
- Same-instance action-before-correction custody, locality/source checks and
  complete resource admission pass.

If the marginal reference also achieves 28 edits, the mechanism-superiority
claim does not pass, even if both satisfy the absolute task criterion. Report
those two conclusions separately rather than changing the criterion. Also report
per-factor pair counts, explicit STOP, canonical tuple versus equivalent edit,
location/payload/EOS/rejection/process errors, all eight acquisition rounds and
all before/after reading results. Partial improvement remains descriptive when
the conjunction fails. No alternate decoding, parameter tuning, extra epochs or
endpoint-conditioned architecture change occurs within this fixed run.

## Complete scope and admission

With five arms and the proposed allocation, full exposure is 1,280 acquisition
actions plus 240 endpoint actions: **1,520 actual verifications**, and 200
reader-only old-panel calls. Exact inherited TRAIN teaching totals are 2,400
reader symbol offers and 3,200 action labels. Actual enabled publications differ
by control and must be counted, not inferred from offers. There are no motor
demonstrations. One source-free endpoint worker keeps the actual pending model
through bounded proposal/execution-envelope/acknowledgement exchange; it never
receives a teacher or task grade.

Keep 32 TRAIN + 28 fresh + 12 old tapes per arm: 72 states, or 360 total. With
unchanged numerical model/tape storage, the nominal five-model plus tape tensor
payload is `5*634432 + 360*656904 = 239657600` bytes. This is a shape estimate,
not a process-peak bound. Both cost and full must retain/export/load that entire
same payload; competition adds actual trace/transient buffers even though its
fixed wiring adds no slow parameters. Adapt source-free inventory, metadata,
compact receipts and independent audit explicitly for one-cursor free versus
all-address teaching. The old finite all-branch free serializer is not compatible.

Propose the same four TRAIN cost IDs per arm and every exact endpoint/panel.
Add one disposable maximum-geometry competitive/marginal cap per arm and four
shared supplied transport-category probes. This is 20 regular cost actions +
240 endpoints + five caps + four categories = **269 cost verifications**.
Regular cost teaching offers 35 reader symbols and 50 action labels; if each cap
retains its declared 17-symbol/three-head correction, total cost offers are 120
and 65 respectively. Review the cap's actual committed cursor, EOS/LIMIT and
teacher geometry prospectively; do not inherit an unverified marginal free claim.
All engineering probes remain outside skill scores.

Retain the 900-second / 2,048-MiB ceiling and the separate stage-max projection:
sum per-arm maxima of complete model, actual action and journal stages, guarded
by caps/category coverage, multiplied by `2*256`, plus twice the measured
non-regular residual and 30 seconds. Independently measure complete audit row
verification maxima and fixed residual; add its projected full cost before
admitting acquisition. All 240 synchronous endpoint exchanges and 200 panel
calls occur in cost as well as full, and belong to the measured residual.

Freeze line/tree and live-record bounds only after an authored maximum-geometry
serializer check includes the actual 8,128 comparator activities/currents. Do
not silently omit them or reuse a bound that only covered the older payload
receipt. Memory must include parent and worker, all retained tensors, runtime
imports, prior authentication/loading, copy overlap and completed independent
audit. Reuse the existing declared run/audit reserve policy only after its
accounting is recomputed for the fifth arm and 360 tapes. A rejected cost closes
this attempted configuration; it does not authorize retries or ceiling changes.

Root selection, exact roster source/data QA, complete source freeze and fresh
measured admission remain prerequisites. This is one proposed integrated
milestone, not a queue of alternative experiments or a general SWE claim.
