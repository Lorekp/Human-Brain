## Checkpoint, disk and restore cost

One route's numeric payload is91,061,944 tensor bytes. Initial two payloads,
24 source changes and at most four online corrections produce at most30 numeric
payload versions:2,731,858,320 tensor bytes (about2.55 GiB), plus serialization
and metadata. Free/counter-only changes reuse authenticated payloads. If the
runner additionally exports a complete final two-route checkpoint, add182,123,888
tensor bytes; do not silently count it as reuse. No garbage collection of prior
payloads is assumed.229 boundary metadata files and229 intent records plus HEAD,
journals, complete execution artifacts and source copies also occupy disk.
The conservative payload guard alone permits15 GiB across30 files; actual free
disk must cover the planned files and temporary rename copy without relying on
the2048 MiB memory guard. Witness author checks remain separate declared work.

Even with payload reuse, begin.inspect and commit._boundary each rehash the
previous two route files. Across228 transactions this reads approximately
83,048,492,928 tensor bytes, plus serialization overhead. Commit hashes both live
models/tapes at entry and end:83,412,740,704 bytes across229 boundaries, before
derived-cache validation and metadata hashes. Its two _actors calls cause916
actor validations; the unchanged event-bank unused-tail check alone contributes
38,287,214,404 validation values at398 owners. These are mandatory existing
checks, not an instruction to weaken custody.

With begin→capture_frontiers→commit, each transaction hashes three current and
two prior journal/execution frontiers. Exact bytes are
sum_t(3*J_t+2*J_(t-1)) plus the analogous execution inventory, not merely final
journal size. Delta parsing and file enumeration add cost. Source/manifest
bindings are checked four times per noninitial transaction (914 checks including
the initial commit's two, plus create/open/final inspection). This makes complete
integrity/capture time a plausible bottleneck even when no tensor is rewritten.

A clean run needs no checkpoint restore after initialization. Restore is not
precharged as if it happened and is not an automatic retry. If separately
authorized later, it constructs two fresh actors, reads/hashes and decodes two
route payloads, prevalidates both before publication, and reconstructs every
view/self wiring twice (explicit prevalidation then public strict loader).
Decoded two-route numeric storage adds182,123,888 bytes; current raw input adds
one route's serialized bytes, with tape restore copies and derived scratch.
No source or teacher replay is permitted. Dirty in-flight intent forbids silent
continuation; report its bounded but unknown interrupted exposure.

## Necessary complete-run instrumentation and limits

Preserve per-call prediction, acknowledgement, correction and source work,
including discarded proposals. Keep parent ingest-row model hashes for the
**combined actor** separate from nested source-feedback hashes of the reader.
Count scalar source/teacher symbols, old-prior calls, actual frees/decisions,
child starts/returns/timeouts, appends, new branches/exhaustion and final slots.
Do not infer offers from payload length when an interrupted call has no receipt.

Record separate wall times for initialization/reference restoration, source
transactions, free model calls, teacher/ack calls, real action/apply/capture,
journal encoding/append/flush, checkpoint begin, frontier capture and checkpoint
commit. Commit's current elapsed field excludes begin/capture. Persist cumulative
checkpoint work and per-boundary deltas; payload reuse does not imply zero work.
Track actual payload file sizes/version count, snapshot tensor bytes and peak
row sizes. Snapshot currently reports a count of uninstrumented validation
passes; do not convert that scalar into invented per-gate counts. Watchdog
elapsed/owned-tree peak and the independent saved-review monitor close the ledger.

At most two retained actors, one active transaction, one full source/teacher
stage, one action block and one sequential snapshot make2048 MiB plausible from
named buffers. Python/Torch allocator, JSON materialization, snapshots, child RSS
and implementation lifetimes prevent a proof of RSS admission from these sums.
No QA latency is extrapolated. The prior V6 attempt exhausted840.4533474 seconds
after182 rows; its source did not perform new source teaching or per-transaction
checkpoints and its neuronal/output trajectory differs. Tournament savings alone
cannot predict V7 completion. The principal risks are long output trajectories,
unchanged all-owner/context computation, and whole-state/journal custody traffic.
Measure them in this one complete guarded session; no additional speed gate or
competing optimization implementation is selected by this plan.
