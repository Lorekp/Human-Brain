## 2. `test_competitive_receipt_policy_and_stable_prior`

Build exactly three separate small reader receipt objects, N=2 and two decisions
(A then EOS): competitive free, full-population marginal free, and inherited
full-population teacher. Use the same helper conventions as node1, without
action heads. Marginal free has uniform branch beliefs but one-hot byte mixtures;
teacher has uniform branch beliefs/mixtures and its proper teacher statistics.

The competitive fixture has both scores equal to the **largest finite float32**,
constructed as `float.fromhex('0x1.fffffep+127')`, zero pair current and winner0.
Its diagnostic prior is `[-log(2), -log(2)]`. Stable validation must compare
shifted scores and their log normalizer; `score-logsumexp(scores)` would lose
`log(2)` at this scale and incorrectly demand zero. No actual Tensor is used.

Compact/validate all three under their exact explicit policies, assert the
competitive and marginal free schemas differ and the teacher keeps its original
population semantics. Require five expected rejections: competitive free as
marginal free; marginal free as competitive free; teacher as competitive free;
competitive free as teacher; and an unexpected compact schema field. No guessing
the expected phase solely from width, kind or generation presence. A competitive
model's inherited corrective receipt is explicitly all_address_teacher.

## 3. `test_competitive_receipt_trace_tampering_and_bounds`

Build a fresh N=2 competitive reader object; do not depend on node2's output
files or repeat its marginal/teacher baselines. Here scores are `[1., 0.]`, pair current1,
comparator true, winner currents `[0.,-1.]`, winner0, and diagnostic prior is
computed from shifted exponentials. Make a valid compact baseline first.

Create independent copies and require exactly fourteen expected validation or
compaction rejections, one change per copy:

1. Wrong pair current.
2. Flipped comparator activity.
3. Wrong winner current.
4. Wrong winner activity.
5. Wrong winner index.
6. Wrong diagnostic log prior.
7. Missing competition trace.
8. Wrong competition work count.
9. Two-wide actual free initial belief replacing its true one-wide belief.
10. Observed free token disagrees with the largest mixture output.
11. Raw step prior differs from the previous actual posterior.
12. Raw cursor differs from the winner's deterministic forward path.
13. Raw final belief differs from the last actual posterior.
14. An extra compact-step field attempts to reintroduce an unchecked cursor.

Cases11–13 exercise the raw compactor before omission. The others exercise the
independent compact validator with the declared competitive policy. No malformed
case should silently dispatch into marginal or teacher handling.

Also require two separate expected guard rejections using actual production
bounds, with no patched constants: an ASCII-JSON expansion case consisting of
U+0080 repeated `LINE_LIMIT//6+1` times has a small Python string tree but exceeds
the encoded-line limit; a list of repeated integer zeros sized from
`TREE_LIMIT//sys.getsizeof(0)+1` exceeds recursive tree accounting while its JSON
line remains smaller than the line limit. Assert those preconditions explicitly
before asking `bounded_record` to reject. Do not write either oversized row.
